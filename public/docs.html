Quick start

Three steps. No account, no API key, no SDK — the player is a plain URL.

01

Find the id

Open the title on themoviedb.org. The number in the URL is the id — …/tv/94605-arcane → 94605. IMDb ids (tt15239678) work too.

02

Build the URL

Movies: /embed/movie/{id}. TV: /embed/tv/{id}/{season}/{episode}. Add options as query parameters.

03

Embed it

Put the URL in an <iframe> with allowfullscreen. That's it — the player handles servers, audio, subtitles and resume.

<iframe
  src="https://your-worker.example/embed/tv/94605/1/1"
  width="100%" height="100%"
  frameborder="0"
  allowfullscreen
  allow="autoplay; fullscreen; encrypted-media; picture-in-picture">
</iframe>

Documentation

Complete reference guide for embedding and customizing the player on your website.

Movie Embed GET

Endpoint

GET https://your-worker.example/embed/movie/{id}?t=0

Required parameters

{id}Movie identifier — TMDB (numeric, e.g. 693134) or IMDb (tt15239678)

Optional parameters

tStart the video at a position — seconds (t=754), 1h2m3s or 12:34. Also accepted as start. Applies once, to the link that was opened.
subDefault subtitle language (en, es, ar, …), matched against the available tracks
langPreferred audio language when the title has several dubs (hi, en, ta, …)
serverDefault server for the player — one of the ids listed under Status (goldmine). Unknown ids fall back to the primary server.
autoskip1 skips intros and recaps automatically (credits keep the manual Next Episode button); 0 turns it off. The viewer's choice is remembered.
colorAccent color as a hex code (16A085, #e50914) or a name: netflix, red, yellow, blue, purple, green, pink, orange. Default is monochrome.
brandingText shown as the player branding on the connect screendefault: LOL Embed
backfalse hides the back button in the top-left corner
originOrigin of your page (https://watch.example). Locks the postMessage API to that origin — recommended when you control the player.

TV Show Embed GET

Endpoint

GET https://your-worker.example/embed/tv/{id}/{season}/{episode}?autoskip=1

Required parameters

{id}TV show identifier — TMDB (numeric, e.g. 94605) or IMDb (tt11126994)
{season}The season number (1-based)
{episode}The episode number (1-based)

Optional parameters

tStart position — seconds, 1h2m3s or 12:34 (also start). One-shot: it does not carry over to the next episode.
subDefault subtitle language (e.g. en, es, fr)
langPreferred audio language for multi-audio titles
serverDefault server (goldmine)
autoskip1 auto-skips intro / recap / preview segments. Credits always show a manual Next Episode button; the next episode plays after an 8-second countdown when the episode ends.
color, branding, back, originSame as for movies (see above)

Other URL forms

Every form below serves the same player and accepts the same query parameters. Use whichever fits your router.

FormPatternExample
Path (movie)/embed/movie/{id}/embed/movie/693134
Path (TV)/embed/tv/{id}/{season}/{episode}/embed/tv/94605/2/1
Query/embed?type={movie|tv}&tmdb={id}&s={season}&e={episode}/embed?type=tv&tmdb=94605&s=1&e=1
Short (movie)/movie/{id}/movie/693134
Short (TV)/tv/{id}/{season}/{episode}/tv/94605/2/1
IMDb id/embed/movie/{imdb}/embed/movie/tt15239678
When the viewer moves to another episode the player rewrites its own URL in place (history.replaceState) using the form it was opened with, so a reload resumes the episode that is actually playing. A season or episode that is omitted defaults to 1.

Basic iframe

The player is served with Content-Security-Policy: frame-ancestors *, so it can be embedded on any site. Always allow fullscreen and autoplay.

<iframe
  src="https://your-worker.example/embed/movie/693134"
  width="100%" height="100%"
  frameborder="0"
  allowfullscreen
  allow="autoplay; fullscreen; encrypted-media; picture-in-picture">
</iframe>

Responsive 16:9 player

Wrap the iframe in a container with an aspect ratio and let it fill the box. The player adapts its own layout below 720 px wide (compact controls, centred transport).

React / Next.js

export function Player({ type, id, season = 1, episode = 1, options = {} }) {
  const base = "https://your-worker.example";
  const path = type === "movie" ? `/embed/movie/${id}` : `/embed/tv/${id}/${season}/${episode}`;
  const query = new URLSearchParams(options).toString();
  return (
    <div style={{ position: "relative", aspectRatio: "16 / 9" }}>
      <iframe
        src={`${base}${path}${query ? `?${query}` : ""}`}
        style={{ position: "absolute", inset: 0, width: "100%", height: "100%", border: 0 }}
        allowFullScreen
        allow="autoplay; fullscreen; encrypted-media; picture-in-picture"
      />
    </div>
  );
}

// <Player type="tv" id={94605} season={1} episode={1} options={{ autoskip: 1, sub: "en" }} />

Good to know

  • Sandboxing. Prefer no sandbox attribute. If your CSP requires one, it must include allow-scripts allow-same-origin allow-forms allow-popups allow-popups-to-escape-sandbox allow-presentation — the player stores preferences in localStorage, opens fullscreen and may open windows.
  • Referrer. Leave the browser's default referrer policy on the iframe. The player identifies your site to the backend through the parent origin; stripping it (referrerpolicy="no-referrer") still works, but your site shows up as anonymous.
  • Autoplay. Browsers only allow unmuted autoplay after a user gesture on your page. The player starts automatically when it may and shows a centre play button otherwise.
  • Resume & preferences. Progress, subtitle/audio choices, volume and quality live in the viewer's localStorage for the player origin — nothing to wire up on your side.
  • Deep links. Append ?t= to open an episode at a timestamp; the player's Settings → Copy link at current time creates such a link and also raises a share event you can intercept.

Query parameters

All parameters work on every URL form. Values are case-insensitive unless noted.

ParameterValuesDescription
colorhex / nameAccent color for the progress bar, buttons and highlights. 16A085, #e50914 or netflix · red · yellow · blue · purple · green · pink · orange. The default theme is monochrome.
brandingtextName shown on the connect screen (defaults to LOL Embed). Keep it short; it is rendered as text, never as HTML.
backfalse / 0Hides the back button. When shown, pressing it posts a back event to your page (see Events) and otherwise goes back in history.
sublanguage codeSubtitle language to enable on load (en, pt, ar, …). Matched against the resolved tracks. A viewer's own choice for that title is remembered and wins on later visits.
langlanguage codePreferred audio language for titles with several dubs (hi, en, ta). Also remembered per title.
t / startseconds · 1h2m3s · 12:34Start position. Beats the saved resume position for the link that was opened; not re-applied when the viewer changes episode.
autoskip1 / 0Automatically skip intro, recap and preview segments. Credits are never auto-skipped (the Next Episode button is shown instead). Persists for the viewer.
serverserver idServer to try first (goldmine). When it fails the player falls through to the next one automatically.
originorigin URLOnly accept postMessage commands from, and deliver events to, this origin. Use it for watch-party or sync integrations.

Listening to player events

The player posts a message to your page for everything that happens. Each message carries source: "lol-embed-player", type: "LOL_EMBED_PLAYER_EVENT", the event name and the full state snapshot — you never need to ask for the state after an event.

const PLAYER_ORIGIN = "https://your-worker.example";

window.addEventListener("message", (e) => {
  if (e.origin !== PLAYER_ORIGIN) return;
  const m = e.data;
  if (!m || m.source !== "lol-embed-player" || m.type !== "LOL_EMBED_PLAYER_EVENT") return;

  switch (m.event) {
    case "timeupdate":   console.log(m.currentTime, "/", m.mediaDuration); break;
    case "statechange":  console.log(m.previousState, "→", m.state);        break;
    case "episodechange": console.log("now S", m.season, "E", m.episode);   break;
    case "ended":        showMyOwnUpNextRail();                              break;
    case "share":        navigator.clipboard.writeText(m.url);              break;
    case "back":         history.back();                                    break;
  }
});

Event names

initloadstartsourcechangereadyloadedmetadatadurationchangeplayplayingpausewaitingseekingseekedtimeupdateratechangevolumechangeendederrorstatechangeserverchangeepisodechangeaudiotrackchangesubtitlechangefullscreenchangeshareback
  • init is sent as soon as the player script is ready, before anything loads — a good moment to send your first commands.
  • timeupdate fires about four times per second while playing.
  • statechange is de-duplicated (one message per transition) and carries previousState.
  • error carries error and serverExplanation; share carries url and time; episodechange carries season and episode.
  • With ?origin= on the embed URL events are delivered only to that origin; otherwise to the parent page.

Controlling the player

Send commands with iframe.contentWindow.postMessage({ type: "LOL_EMBED_PLAYER_COMMAND", command, requestId, ...args }, PLAYER_ORIGIN). Only the page that contains the iframe is obeyed (with ?origin=: only that origin). Include a requestId and the player answers with { type: "LOL_EMBED_PLAYER_RESPONSE", requestId, ok, error, ...snapshot }.

const PLAYER_ORIGIN = "https://your-worker.example";
const player = document.querySelector("iframe").contentWindow;

function send(command, args = {}) {
  const requestId = `${Date.now()}-${Math.random().toString(36).slice(2)}`;
  return new Promise((resolve) => {
    const onMessage = (e) => {
      const m = e.data;
      if (e.origin !== PLAYER_ORIGIN || !m || m.type !== "LOL_EMBED_PLAYER_RESPONSE" || m.requestId !== requestId) return;
      window.removeEventListener("message", onMessage);
      resolve(m);
    };
    window.addEventListener("message", onMessage);
    player.postMessage({ type: "LOL_EMBED_PLAYER_COMMAND", command, requestId, ...args }, PLAYER_ORIGIN);
  });
}

await send("play");
await send("seek", { time: 754 });
await send("setSubtitle", { lang: "en" });
const { currentTime, mediaDuration } = await send("getState");

Watch-party sync in 20 lines

Drive everything from statechange, seeked and timeupdate; compare sourceId + mediaDuration to make sure every participant plays the same cut.

// host side
window.addEventListener("message", (e) => {
  const m = e.data;
  if (e.origin !== PLAYER_ORIGIN || m?.source !== "lol-embed-player" || m.type !== "LOL_EMBED_PLAYER_EVENT") return;
  if (["statechange", "seeked", "episodechange"].includes(m.event)) {
    socket.send(JSON.stringify({ state: m.state, time: m.currentTime, season: m.season, episode: m.episode, sourceId: m.sourceId }));
  }
});

// guest side
socket.onmessage = async ({ data }) => {
  const r = JSON.parse(data);
  if (r.season != null) await send("setEpisode", { season: r.season, episode: r.episode });
  if (Math.abs((await send("getTime")).currentTime - r.time) > 1.5) await send("seek", { time: r.time });
  await send(r.state === "playing" ? "play" : "pause");
};
Legacy shapes are still accepted so older integrations keep working: a bare { command: "play" | "pause" | "seek" | "setVolume" | "nextEpisode" } and { type: "VIDBOLT_PLAY" | "VIDBOLT_PAUSE" }.

FAQ

        

        

          
Which ids are supported?

          
TMDB ids (the numeric id from themoviedb.org URLs) and IMDb ids (tt…). IMDb ids are translated to the TMDB entry once and cached; the TMDB id is what the player and the host API report.

        

        

          
A title doesn't play. What now?

          
The player tries every server before giving up and then shows the server list on the error screen, so viewers can retry another one. If nothing works for a title, it is simply not available upstream right now — try again later.

        

        

          
Can I style the player?

          
Use color for the accent, branding for the name, back=false to drop the back button. The layout itself is fixed and adapts to the iframe size.

        

        

          
Is there a rate limit or an API key?

          
No key is needed to embed. Please embed the player rather than scraping its backend; sites that abuse the service can be blocked by the operator.

        

        

          
Will it work inside a sandboxed iframe or a strict CSP?

          
Yes, if you allow scripts, same-origin storage, fullscreen and popups (see Implementation → Good to know). Your frame-src / child-src directive must list https://your-worker.example.
